# 请求和响应日志

在「系统设置 → 运维设置 → 日志维护」中配置「请求和响应日志」，保存后生效：

| 模式 | `LogRequestDetailMode` | 行为 |
| --- | --- | --- |
| 关闭（默认） | `0` | 不采集或保存请求/响应详情。 |
| 仅失败记录 | `1` | 仅保存原有代理流程中失败尝试的请求/响应详情。 |
| 所有请求都记录 | `2` | 同时保存成功和失败尝试的请求/响应详情。 |

该设置控制原有请求详情功能，独立于「记录额度消费」和错误日志开关。详情沿用 `request_details` 表和使用日志中的「请求详情」入口，无需新增数据库字段。重试按每次上游调用记录，同一次尝试只保存一次。

HTTP 响应在读取过程中采集，支持普通响应和 SSE 流式响应；流式详情保存代理实际读取到的原始数据，不会为日志额外等待或读取剩余流。失败模式也会临时采集响应，仅在失败时写入数据库。尚未进入原有详情采集流程的请求（例如鉴权或参数校验被拒绝）不在此功能范围内。

兼容旧配置 `LogRequestDetailEnabled`：`false` 对应关闭，`true` 对应仅失败记录。数据库中同时存在新旧配置时，以 `LogRequestDetailMode` 为准；旧客户端提交布尔开关也会转换并保存为新模式。新模式只接受 `0`、`1`、`2`，非法值不会覆盖已保存的配置。
