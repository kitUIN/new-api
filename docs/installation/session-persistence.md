# 更新和重启后保留登录状态

登录 Cookie 的有效期为 30 天，服务端使用会话密钥验证 Cookie。旧版本未配置 `SESSION_SECRET` 时，每次启动都会生成新密钥，因此更新或重启会导致所有已登录账号需要重新登录。

现在未配置 `SESSION_SECRET` 时，首次启动会自动生成随机密钥并写入主数据库的内部 `SessionSecret` 记录，后续启动复用。保留原数据库即可跨更新、重启、容器重建保留有效登录。共用同一数据库的多个节点会使用同一个自动生成的密钥。

如果已经配置 `SESSION_SECRET`，程序继续优先使用该环境变量。请保持其值不变，并确保所有节点配置一致；不要混用显式配置与自动生成方式。未单独设置 `CRYPTO_SECRET` 时，它沿用会话密钥。

部署旧版本时，也可以通过配置固定的 `SESSION_SECRET` 解决重启掉线。在服务器上运行 `openssl rand -hex 32` 生成随机值，然后将其保存到服务实际加载的环境配置中：

```dotenv
SESSION_SECRET=替换为生成的随机值
```

二进制部署可写入工作目录中的 `.env` 或 systemd 服务的 `EnvironmentFile`。Docker 部署需要通过 `environment` 或 `env_file` 将变量传入容器。配置一次后长期保留，不要在每次启动或更新时重新生成，也不要使用示例值 `random_string`。

旧版本使用的临时密钥无法在进程退出后找回，首次应用修复可能需要重新登录一次。之后，只要数据库或显式密钥保持不变，有效期内的登录不会因应用重启而失效。主动退出、Cookie 过期或被清除、更换访问域名、主动修改密钥仍可能需要重新登录。

自动生成的密钥不通过设置接口展示或修改。若数据库读取、写入失败或已有密钥无效，程序会停止启动并报告错误；应恢复数据库或配置固定密钥后重新启动。
