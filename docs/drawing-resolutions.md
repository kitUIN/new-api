# 绘图尺寸与分组路由

绘图页面的尺寸下拉框会为所有引用图、上传图显示“图1尺寸、图2尺寸……”；编号与缩略图一致。选择后按该图片的实际宽高生成，删除已选图片时恢复预设比例和分辨率。预设分辨率支持 1K、2K、4K。所有明确指定的尺寸，其宽和高都必须为 16 的倍数；不符合的原图尺寸选项禁用并提示原因，后端也会拒绝该尺寸。图片仍可作为参考图上传，不会自动修改原图尺寸。内置 3:4、4:3 预设使用就近的 16 倍数尺寸。

在“分组定价”选中计费分组后，使用“绘图分辨率”勾选允许的规格。配置存储在 `group_ratio_setting.group_drawing_resolutions`，未配置的分组兼容原行为，默认允许全部规格；显式空数组表示停用该分组的绘图。

例如：

```json
{"A":["1K"],"B":["2K"],"C":["4K"]}
```

绘图入口继续使用 `gpt-image` 分组。将它设置为组合分组，添加 A、B、C，并为各成员配置支持的绘图模型。选择 2K 时只会选择支持 2K 的成员（本例为 B），且保留组合分组原有成员顺序、模型限制、熔断和重试机制。重试不会进入不支持该分辨率的成员。普通 `gpt-image` 分组及旧版固定渠道组合也支持在根分组配置分辨率限制。

组合根分组自身的限制与成员限制同时生效。例如根分组仅勾选 1K，则成员的 2K 也不会在该绘图入口可用。仅有部分成员支持当前尺寸的模型会按尺寸动态筛选；没有匹配成员时拒绝请求。

分辨率按实际请求尺寸的短边判定：短边不超过 1024 为 1K，不超过 2048 为 2K，不超过 4096 为 4K，超过则拒绝。`auto` 或省略尺寸兼容为 1K。原图尺寸同样执行该规则，不能通过前端参数绕过分组限制。尺寸是否被上游模型支持仍由对应供应商决定。

计费使用实际选择的成员分组，通过现有 `ResolveGroupRatioAt` 流程保留定时倍率和日志快照。组合分组的余额提示显示“使用成员分组倍率”，避免用组合根分组倍率给出错误的次数估算。
