# 上游用量监控

管理员在「数据看板 → 上游用量」中添加上游：

1. 填写 Base URL、access_token 和 refresh_token。
2. 设置采集间隔（1–1440 分钟，默认 5 分钟）。
3. 添加该上游的 account_id，可将每个账号绑定到多个本地分组。
4. 保存后由主节点自动采集，也可点击「立即采集」。

后台每 15 秒检查一次到期配置，最多同时采集 4 个上游。同一个上游的账号顺序采集；采集期间不会并发刷新其令牌。单次 HTTP 请求超时为 30 秒。

用量接口为 `GET {base_url}/api/v1/admin/accounts/{account_id}/usage?timezone=Asia%2FShanghai`，使用 Bearer access_token。遇到 HTTP 401 时调用 `POST {base_url}/api/v1/auth/refresh`，请求体为 `{"refresh_token":"..."}`，保存返回的新令牌后重试。每次上游采集最多刷新一次，避免失效凭据导致无限重试。

令牌仅保存在服务端，查询配置不会返回令牌。编辑时留空保留已有令牌；更换 Base URL 时须重新填写两个令牌，并清除旧地址的用量快照。

分组监控中的电池替代 Juice 及其历史图：

- 百分比为绑定账号的平均 **7d 剩余量**，即各账号 `100 - utilization` 的平均值。
- 剩余量小于 10% 为红色，10%–30% 为黄色，大于 30% 为绿色。
- 右下角圆环为平均 **5h 剩余量**。所有账号 5h 使用量为 0 时隐藏圆环；平均剩余量为 0 时显示警告。
- 未绑定账号、任一绑定账号获取失败或快照超过「两倍采集间隔 + 60 秒」时，直接隐藏电池按钮及百分比。有效的 0% 剩余量仍正常显示。
- 点击电池查看各账号 5h/7d 已用、剩余、重置时间、请求数、tokens、cost 和 standard_cost；不返回或显示 user_cost。失败时可在管理员的上游用量页查看标记为历史数据的最后成功快照。

配置、增删改和手动采集接口 `/api/upstream-usage` 均要求管理员权限。分组用量只读接口 `/api/perf-metrics/upstream-usage` 沿用现有分组监控接口的公开访问方式，仅返回已绑定账号的用量，不返回上游地址或任何令牌。

配置与快照存储于两个独立的 GORM 表，服务启动时自动迁移；不改变渠道余额查询或原有 Juice 后台任务。
