# API Key 分组故障转移

- 状态按 API Key 独立保存于 Redis，同一密钥的不同模型、会话共享当前优先级和连续失败次数。
- 从 P0 开始；连续最终失败达到配置阈值后，切换到下一个优先级。成功请求清零连续失败次数，保留当前优先级。
- 自最后一次通过身份认证的 API Key 请求起，连续 **2 小时无请求**，自动重置为 P0 并清零失败次数。有新请求会重新开始计时，包括随后路由失败的请求及使用该密钥的只读查询；控制台查看密钥列表、详情不会续期。
- 计时以请求进入为准，请求完成不会续期。重置前发出的迟到响应不能恢复旧状态。
- 密钥编辑页仍可手动重置为 P0；同时显示两小时空闲重置规则。
- 下一次请求从 P0 重新选择；如果 P0 分组已关闭、无权访问或没有该模型的可用渠道，仍按原有规则跳过不可用分组。
- 升级时，旧版永久保存的状态按 `updated_at` 判断空闲时间；已满两小时的状态视为 P0，仍活跃的状态在下一次请求时补上过期时间。
- Redis 未启用时，沿用原有行为，不保存跨请求的故障转移状态。
